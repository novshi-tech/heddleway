# 0051 LINE の友だちの表示名で、相手の連絡先を見回りが作る（案）

- 状態: 提案（2026-11-24）。0030 の「名寄せは人とスタンドが付ける」と食い違うので、決まるまで実装しない
- 関連: 0030（Contact とクエリ層の解決）、0049（LINE 公式アカウント）

## 背景

LINE 公式アカウントの相手のアドレスは LINE の userId（`U` で始まる 33 文字）で、トピックの相手・アテンションに名前が出ない。
受け口（業務システム）は受信のたびに友だちのプロフィールの表示名を引いて、イベントに付けて持っている（取れないときは空）。
今のスキルでは、エージェントが受け口で表示名を引き、`POST /contacts` で連絡先を作る（0030）。ただ、エージェントがその手順を踏むまで、共有リストのメンバーには userId しか見えない。
LINE の友だちは応募者・お客さんなどメンバーでない人が多く、メールのように表示名を含むアドレスでもないので、userId のままだとトピックの一覧が読めない。

## 選択肢

1. **見回りが連絡先を作る（推奨）**: 受信のイベントに表示名があり、そのアドレスがどの連絡先にも付いていなければ、見回りがその表示名で新しい連絡先を作ってアドレスを付ける（マスタの変更として記録する。書き手は本体）。
   既にある連絡先に付けることはしない（取り違えが起きない）。名前を直す・まとめるのは、これまでどおり人とエージェント。後から本人が `POST /lists/{id}/identity` で自分のアドレスとして登録したときは、既存の `merge_candidate` の流れでまとめる
2. **今のまま（エージェントが作る）**: 0030 のとおり。スキルに「LINE のトピックを見たら、未解決の相手を表示名で連絡先にする」をはっきり書く。コードは変えないが、エージェントが見るまで名前が出ない
3. **シグナルに表示名を持たせ、クエリ層で見せる**: イベントの形を足す（`SignalObserved` に送り主の表示名）。連絡先は作らない。名寄せのしくみと別に「名前だけある相手」ができ、ほかのコネクタとそろわない

（未定）

## 影響（1 を採ったとき）

- 0030 の決定に「新しい連絡先を作るだけなら、コネクタが、ソースの持つ表示名で作ってよい（既存の連絡先に付けない）」を例外として足す
- 受け口の読む項目に `displayName` を足す（`EVENT_FIELDS`）
- 表示名は受け取った時点の名前。友だちが名前を変えても、作った連絡先の名前は変わらない（直すのは人とエージェント）
