# 0048 本人が「参加中のリスト」をゲートウェイの画面で見られるようにする

- 状態: 提案（2026-11-19）。実装は同じ PR に入れた（末尾の「実装の記録」）
- 関連: 0010（黒子。業務用の画面は持たず、参照専用の画面だけ。認証と可視性は作るときに決める）、0023（ゲートウェイの機能）、0037（共有リストの読者はソースから写す）、0039（個人リストと共有リスト）、0040（表の言葉）、heddleway の ADR 0005

## 背景

リストへの入り方が種類ごとに違い、本人からは自分がどのリストのメンバーなのかが見えない。

- Teams のチャネル・Google Chat のスペースは、ソースのメンバーのうちゲートウェイにサインインしたことのある人が、見回りで自動で読者になる（本人は気づかない）
- Jira のプロジェクトは、自分の Jira をつないでアイデンティティを登録した人だけが読者になる
- 共有メールボックスは、自分でつないで自分の接続で箱を読めた人だけが読者になる
- 個人リスト（メール・タスク・チャット）は、エージェントに頼んでつないだものだけ

確かめる手段は、エージェントに `GET /connections` や `GET /lists` を呼んでもらうことだけだった。参照専用の画面（`/admin`・`timeline.html`）は `MURMUR_TIMELINE_TOKEN` を知る運用者向けで、全データソースが見えるので、メンバーには渡せない。チームに広げる前に、メンバーが自分の目線で「入っているリスト」と「増やし方」を見られる場所が要る。

## 決定（案）

### 1. 画面はゲートウェイの `/features/murmur` に置き、ゲートウェイのサインインで本人を決める

- ゲートウェイの機能（`Feature`）に、任意の `userPage`（リンクの文言と `render(userId)`）を足す。ゲートウェイは `/features/<name>` で Web のセッションを確かめ、本人の User ID で `render` を呼び、返った HTML の断片を自分の枠（ヘッダー・スタイル）に入れて出す。ホームの「このゲートウェイの機能」の行にリンクを出す
- Murmur は新しい公開の経路を足さない。`/murmur/...` の公開の経路は今までどおり Webhook・同意のコールバック・運用者の画面だけで、本人の画面の入口はゲートウェイの側にある（同意の画面 `/features/murmur/consent` と同じ置き方）
- 見えるもの・できることは、スタンドの API と同じ本人の可視性（`deriveViewer`）で決める。画面は参照だけで、操作（つなぐ・外す・担当する）は置かない。操作はエージェントに頼む（0010 の「業務用の画面は持たない」）
- 上流は呼ばない（Murmur の D1 の中だけを読む）。トピック索引を無効にしていても見られる。無効なときは、ゲートウェイが「新しいやりとりは取り込まれない」と添える
- 画面を開いただけでは User の行を作らない（API の入口の `ensureUser` を通さない。名乗るのはエージェントからつないだとき）

### 2. 出すもの

- 呼び方（なければ、エージェントへの頼み方）
- 個人のリストと共有のリストを分けて、リストごとに種類・取り込みの状態（`GET /connections` の `status` と最後の取り込み）・開いているトピックのうち担当とアテンションの件数・割当待ちの件数（共有のリストだけ）・メンバー（共有のリストだけ。呼び方のない人は、アドレスのままの連絡先の名前を出さず「呼び方なし」にする）。止まっている・外しているときは、直し方を添える
- リストを増やすには: 本人の IdP（ゲートウェイの User ID の `entra_` / `google_`）で個人リストにできるもののうち、まだないものと、エージェントへの頼み方。共有リストは、デプロイが許すサービス（`MURMUR_SHARED_SERVICES`）ごとの入り方だけを書く

### 3. メンバーでない共有リストは、名前も出さない

「このチームには Jira の○○プロジェクトのリストがある」と見せると、そのプロジェクトを読めない人にもスペースがあることが分かる。共有リストの読者はソースの読める人から写すので（0037）、見せてよいかはソースが決める。画面には本人が読者のリストだけを出し、入り方は種類ごとの説明に留める。

## 考えたほかの案

- **Murmur の公開の経路（`/murmur/me` など）に置き、Murmur が本人を確かめる**: ゲートウェイの Web のセッション（クッキー）を Murmur が読むことになり、口（`ports/gateway.ts`）に認証の手段を足す必要がある。ゲートウェイの枠（ヘッダー・スタイル）も別に持つことになる
- **ゲートウェイが Murmur の REST（`/api/murmur/connections`・`/lists`）を本人のトークンで呼んで、ゲートウェイの側で描く**: Murmur の中身はそのままだが、ゲートウェイの中核が Murmur の API の形を知ることになる（0023 の vertical slice に反する）
- **運用者の画面（`/admin`）に本人の目線を足す**: トークンで守る画面と、本人のセッションで守る画面を混ぜると、可視性の取り違えが起きやすい

## 残ること

- トピックの一覧（自分の担当・割当待ち・返事待ち）を画面に出すかは、使われ方を見てから決める。出すとしても参照だけ
- 件数は開いているトピックを毎回数える（一覧と同じ範囲の読み方。0047）。リストが増えて重くなったら考える
