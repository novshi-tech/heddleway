# Google Chat のスペースのタスクを共有リストにする前に確かめた（0045 の S0、前半）

日付: 2026-11-17。Google Workspace の組織のデプロイで、本人（委任）のゲートウェイの `tasks` の接続から、ゲートウェイの `api_get` で呼んだ。タスクの中身は形と件数だけを見た。Google Chat の API は、ゲートウェイにまだサービスがないので呼んでいない（後半は Chat のサービスを足してから）。

## タスクのリスト（`users/@me/lists`）

| 項目 | 結果 |
| --- | --- |
| リストの一覧 | 本人が作ったリスト 3 つ（既定の「マイタスク」と 2 つ）だけ。**スペースのタスクのリストは出てこない** |

## 既定のリストのタスク（`lists/{既定}/tasks`）

| 項目 | 結果 |
| --- | --- |
| `showAssigned=true`（と `showCompleted`・`showHidden`） | 通る。本人のタスク 6 件に混ざって、**スペースで本人に割り当てられたタスクが 4 件**出る |
| 割り当てられたタスクの印 | `assignmentInfo` に `surfaceType: "SPACE"`、`spaceInfo.space: "spaces/<ID>"`、`linkToTask`（スペースの URL。メッセージやタスクそのものは指さない） |
| どのスペースか | 3 つのスペースにまたがる。同じスペースのタスクは同じ `spaces/<ID>` |
| ほかの項目 | 本人のタスクと同じ（`id`・`title`・`status`・`completed`・`hidden`・`updated`・`webViewLink`）。担当者を表す項目はない（このリストの持ち主＝担当者） |
| `showAssigned` なし | 割り当てられたタスクは出ない（ドキュメントのとおり既定は false）。**今の Google Tasks のコネクタはこの印を付けていないので、スペースのタスクは今の個人リストに入っていない** |

## 試したが通らなかったこと

- スペースの ID（`spaces/<ID>` の `<ID>`）をタスクのリストの ID として `lists/<ID>/tasks`・`users/@me/lists/<ID>` に渡す → どちらも 400（`Invalid task list ID`）

## Google のヘルプ（2026-11-17 に読んだ）

- Tasks のヘルプ「Get started with shared tasks」（tasks/answer/11549608）: 割り当てられた共有のタスクは、本人の既定のリストに入る（別のリストに移せる）。アカウントが消えると、割り当てが外れて**スペースには残る**。タスクが消えても、Chat では**関連するメッセージはスペースに残る**
- Chat のヘルプ「Create & assign tasks in Google Chat」（chat/answer/9920628）: タスクはスペースのメンバーが作り、作ったスペースで見る。割り当てられた人の個人のリストにも出る。**だれかがタスクを作る・更新すると、スペースに通知（メッセージ）が出る**

## 公式の API ドキュメント（2026-11-17 に読んだ）

- Tasks API の `tasks.list` の `showAssigned`: 「現在のユーザーに割り当てられたタスクを返すか」。割り当てのないタスク・他人のタスクを返す口はない
- Chat API の Message のリソース・`spaces.messages.list`、Workspace Events の Chat のイベントの種類（message・membership・reaction・space・availability・読み取りの状態）には、タスクの語が 1 度も出てこない。タスクのイベントやタスクの項目は**ドキュメントにない**
- したがって、スペースに出るタスクの通知が `messages.list` に出るかは、ドキュメントからは決まらない。出るとしても、形は文書化されていない（実物で確かめるしかなく、黙って変わりうる）

UI でスペースのメンバー全員が見られるタスク（割り当てのないものも含む）は、スペースの側にある。公開の Tasks API から見えるのは、割り当てられた人の写しだけ。

## 分かったこと

1. スペースのタスクを、スペースのタスクとして一覧する API はない（Tasks API にも Chat API にも見当たらない。調べた範囲）。見えるのは、**割り当てられた人の既定のリストの写し**だけ
2. したがって、1 人の委任では、そのスペースの「自分に割り当てられたタスク」しか読めない。割り当てのないタスクと、つないでいない人に割り当てられたタスクは読めない
3. `spaceInfo.space` は Chat API のスペースの名前（`spaces/<ID>`）と同じ形なので、Chat のスペースの共有リストと突き合わせられる

## 後半で確かめること（Chat のサービスを足してから）

- Chat API（`spaces.list`・`spaces.messages.list`・`spaces.members.list`）が、委任で読めるか。`users/{id}` の ID がゲートウェイの User ID（`google_<sub>`）の sub と同じか
- **いちばん大事**: ヘルプにある「タスクを作る・更新するとスペースに出る通知」が、Chat API の `messages.list` に出るか。出るなら、どの形か（送り手、テキスト、カード、タスクの ID・タイトル・担当・状態が読めるか）。読めるなら、割り当てのないタスクも、つないだ人 1 人の委任で写せる（0045 の決定 6 の経路 A）
- タスクの割り当てを A から B に替えたとき、A の写しは消えるか（`deleted`）、B の写しの `id` は A のものと同じか
- 割り当てられたタスクを完了にすると、スペースの側でも完了になるか（逆も）
- `showAssigned` と `updatedMin`・`showDeleted` を一緒に使えるか
