# 0010 ゲートウェイの画面をホーム画面に置けるアプリ(PWA)にし、前に開いた機能の画面をすぐ出す

- 状態: 提案(2026-11-26)。実装は同じ PR に入れた
- 関連: [0005](0005-murmur-as-a-feature.md)(機能として持つ)、トピック索引の [`0051`](../../topic-index/docs/adr/0051-now-page.md)・[`0052`](../../topic-index/docs/adr/0052-now-first-view.md)(今やることの画面)

## 背景

トピック索引の「今やること」は、1 日に何度も開く画面になった。使ってほしい人には事務所の外にいる人も多く、スマホで開く。サーバーの側を速くしても、開くたびに 0.4〜0.6 秒はデータベースの往復を待つ。ホーム画面からアプリのように開けて、開いた瞬間に何かが出ていてほしい。

## 決定(案)

1. **画面はサーバー描画のまま、Service Worker で前に開いた画面を先に出す。** `/sw.js`(スコープは `/`)は、機能の画面(`/features/<name>/...`。同意と無効にする経路は除く、クエリのないもの)のページ遷移だけを扱う。手元に写しがあればそれをすぐ返し、裏でサーバーから取り直して写しを入れ替え、開いている画面の `<main>` を新しい内容に差し替える(`/assets/pwa.js`)。写しがなければ普通に取りに行って、写しを残す。画面が前に戻ってきたときも取り直す。ほかの画面(接続の管理・管理者の画面・サインイン)は今までどおりで、写しを持たない
2. **サインインが切れたら写しを出したまま知らせる。** 取り直しがサインインへのリダイレクトになったら、「サインインが切れたため、前に開いたときの内容を表示しています」とサインインし直すリンクを出す
3. **サインアウトで端末の写しを消す。** `/logout` の応答に `Clear-Site-Data: "cache", "storage"` を付け、写しと Service Worker を消す
4. **ホーム画面に置ける。** `/manifest.webmanifest`(`display: standalone`、アイコンは `/assets/icon-{180,192,512}.png`)。開く先は、本人の画面を持つ最初の機能(トピック索引の今やること)で、なければホーム。すべての画面の `<head>` にマニフェストと `pwa.js` を置き、CSP に `manifest-src 'self'; worker-src 'self'; img-src 'self'` を足す

## 考えたほかの案

- **SPA にして、画面用の JSON をクライアントで描く**: 前の内容をすぐ出す・ホーム画面に置くことは、HTML の写しでも同じようにできる。フロントのビルドと、ブラウザのセッションで呼ぶ JSON の口と、同じ画面の描き方の二重持ちが増える。画面の中で操作(担当する・目を通した)をするようになったら、その操作の分だけ足す
- **ブラウザの HTTP キャッシュに任せる(`cache-control` を緩める)**: 古い内容を出したあとに新しい内容へ差し替える手段がなく、共有の端末で前の人の画面が残る
