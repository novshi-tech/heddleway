# 0051 本人が「今やること」とトピックの経過をゲートウェイの画面で見られるようにする

- 状態: 提案（2026-11-25）。実装は同じ PR に入れた（末尾の「実装の記録」）。決定 2（今やることに出すもの）は 0052 で置き換えた
- 関連: 0010（黒子。業務用の画面は持たない）、0038（担当とアテンション）、0039（個人リストと共有リスト）、0040・0043（表の言葉）、0047（一覧の範囲）、0048（参加中のリストの画面。「残ること」のトピックの一覧をここで決める）

## 背景

本人の「今やること」は、エージェントに「今日やることは?」と聞いて、会話の中に一覧を出してもらうしかなかった。使い始めた人から 2 つの声が出た。

- 会話の中の一覧は、やりとりが続くと流れていって、あとから見返せない。今やることは、少なくともいつでも見られる場所が要る
- トピック索引が何をしているのか（何を集めて、担当とアテンションをどう追っているのか）が、会話だけでは伝わりにくい。集めたものがそのまま並んでいる画面があると伝わる

0048 は「トピックの一覧を画面に出すかは、使われ方を見てから決める。出すとしても参照だけ」とした。これを、参照だけのまま出す。

## 決定（案）

### 1. 置き場所と認証は 0048 と同じ

- ゲートウェイの `/features/murmur` の下に置き、ゲートウェイの Web のセッションで本人を決める。`Feature.userPage` を、根の下の経路（`path`）を受けて題と本文を返す形に広げる（`render(userId, { path, base }) → { title, body } | null`）。ゲートウェイは `/features/<name>` とその下の GET を（同意の画面を除いて）全部 `render` に渡し、`null` なら 404 にする。経路の意味は機能が決める
- 経路: 根（`''`）が「今やること」、`lists` が 0048 の「参加中のリスト」、`threads/<ID>` がトピックの詳細。根と `lists` はタブで行き来する
- 見えるもの・可視性・上流を呼ばない・User を作らないことは 0048 と同じ。見えないトピックの詳細は 404（あることを分からせない）

### 2. 「今やること」に出すもの

本人の担当とアテンション（`my_turn`）と、本人のタスクのリストの開いているタスク（`mine`）を、区分に分けて出す。1 つのトピックは最初に当てはまる区分にだけ出す。

1. 自分の担当: 担当が自分のトピック（ソースの担当者か、担当する操作）。期限の近い順
2. 自分のタスク: 個人リストの To Do・Google Tasks の開いているタスク（タスクのリストがなければ区分ごと出さない）。期限の近い順
3. アテンション: 本人宛て（`named`）を先に、リスト宛て（`list`）をあとに。どちらかをバッジで示す。タスクか FYI かは画面では決めない（0043）
4. 返事待ち: こちらから送って返事がまだのもの。期限を過ぎたものを先に
5. 割当待ち: 共有リストで担当のいないもの。畳んで出す

行には件名・リストの名前・ソースの状態の名前（Jira など）・相手の名前・最後の動き・期限（タスクの期限か返事の期限。過ぎていれば目立たせる）を出す。並べ替え・絞り込みはしない。中身は開いたときのもので、新しく届いたものは再読み込みで出る。

### 3. トピックの詳細に出すもの

API の `GET /threads/:id` と同じ本人の目線（0033 の結んだ先の見え方を含む）で、件名・担当・状態・期限・相手・関連づけたトピック（詳細へのリンク）と、経過（メッセージ・メモ・操作。新しいものが上。長い本文は畳む）を出す。Jira の課題は課題へのリンクを出す（サイトと課題キーで組める）。ほかのソース（メール・Teams・To Do）へのリンクは、写しにソースの URL を持っていないので出さない。

### 4. 操作は置かない

担当する・アテンションを外す・片付けるなどの操作は置かず、画面にはエージェントへの頼み方を添える（0010・0048）。操作を画面に置くかは、この画面の使われ方を見てから、別の ADR で決める。

## 考えたほかの案

- **一覧を Artifact などエージェントの外の画面に書き出す**: 書き出した時点のものになり、トピック索引の可視性の外にデータが出る。いつ開いても同じ場所で、本人の目線で見える画面のほうがよい
- **ゲートウェイが Murmur の REST を本人のトークンで呼んで描く**: 0048 で退けた理由と同じ（ゲートウェイの中核が Murmur の API の形を知ることになる）
- **トピックの詳細を出さず、一覧からソースへ飛ばすだけにする**: ソースの URL を写しに持っていない（Jira だけ組める）。経過が見えることが、トピック索引が何をしているかを伝える一番の手がかりなので、詳細を出す

## 残ること

- 画面に操作（担当する・目を通した）を置くか
- ソースへのリンク（Outlook の webLink・Teams のメッセージのリンク）を写しに持つか
- 件数が増えたときの絞り込み（リストごと・期限ごと）
- 一覧の自動の更新（今は再読み込み）
