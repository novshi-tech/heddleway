# 0054 メッセージに送り主の表示名を添え、トピックの詳細で呼び方に使う

- 状態: 採用（2026-11-28）
- 関連: 0030（アドレスで畳み、名寄せは人とエージェントが付ける）、0049（LINE 公式アカウント）、0051（トピックの詳細の画面）

## 背景

トピックの詳細の経過は、送り主を Contact の名前で呼び、Contact がなければアドレスをそのまま出していた。メールはまだ読めるが、LINE の userId（`U1382…`）や Teams の ID は誰なのか分からない。どのソースも送り主の表示名を返しているのに、取り込みで捨てていた。

## 決定

1. `SignalObserved` に任意の `fromName`（200 字まで）を足す。コネクタはソースが返す送り主の表示名をそのまま入れる: Outlook の From の名前（アドレスと同じなら入れない）、Teams（チャネル・チャット）と Google Chat の表示名、Jira のコメントの書き手の表示名、LINE の友だちの表示名（受け口が保存したもの。受信だけ）
2. `fromName` は名寄せにも、担当・アテンションにも使わない（0030 のまま）。Contact を作らず、名前も書き換えない
3. 呼び方の順は、Contact の名前（呼び方のある人）→ そのトピックで同じアドレスに添えられた一番新しい `fromName` → アドレス。詳細の経過・相手・担当の名前に使う
4. API のタイムラインのシグナルにも `fromName` を出す（あるときだけ）
5. 前からある投影の行やイベントには付かない。保存の形は JSON なのでマイグレーションは要らない

## トピックの詳細で見せる範囲

経過は「誰が・いつ・本文」までをトピック索引で読めるようにし、画像や添付の中身は持たず、元のアプリへのリンクで開く。中身まで写すと、ソースごとに保存と権限の仕組みを持つことになり、依存が増えるため。LINE の画像は、受け口（業務システム）が中身を配る口を持ってから、その画面へのリンクにする。

## 結果

- LINE・Teams の経過が人の名前で読める
- 名前の変わった人は、新しいメッセージから新しい名前になる
